What DTLS-SRTP gives you

✅ Already protected
  • Audio & video frames — AES-128 encrypted
  • Keys derived peer-to-peer via DTLS handshake
  • Server cannot decrypt media even if it tried
  • TLS on signaling channel (gRPC)
❌ Not yet protected
  • SDP offer/answer — server sees DTLS fingerprints
  • No key continuity / identity binding to Signal keys
  • Server can MITM by swapping SDP fingerprints
  • Call metadata (who, when, duration) fully visible
  • srtpKeyParams field — empty Data() placeholder
The gap: DTLS-SRTP is strong for media, but the server is trusted to relay SDP faithfully. If a malicious server swaps the DTLS fingerprint in the SDP, it can perform a man-in-the-middle attack on the call. True E2EE binds the DTLS fingerprint to the Signal identity keys Alice and Bob already have for each other.
