Full E2EE Calls — Three-Layer Model

Option C: media-level, signaling-level, and metadata-level protection

LAYER 1 — Media
DTLS–SRTP
+ fingerprint binding
Alice's SDP offer is encrypted with Bob's Signal session key before hitting the server. The DTLS fingerprint is inside the ciphertext — server can't swap it.

Bob decrypts using the Signal session already established for messages. He verifies it really came from Alice.
📦  CallOffer.encryptedSdpPayload
= Signal-encrypt({ sdpOffer, dtlsFingerprint, timestamp })
LAYER 2 — Identity
Sealed Sender
for calls
The call initiation is wrapped in a sealed delivery token — same mechanism as messages. Server sees "someone is ringing user 9f2a…" but not who.

Only Bob can decrypt the delivery cert and learn it's Alice.
🪪  Reuses existing SealedSenderManager
+ delivery token infrastructure
LAYER 3 — Metadata
Duration
padding
Call duration is a powerful fingerprint. After the real call ends, both sides send SRTP-encrypted silence/padding to the nearest time bucket (1, 5, 15, 30, 60 min).

Server sees traffic for the padded duration, not the real one.
⏱  Bucket: ceil(real duration / bucket) × bucket
Padding: encrypted silence frames
